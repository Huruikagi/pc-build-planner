# Skill 手順の固定検証

この手順は `site-extraction-authoring` の操作順、停止、判断記録を確認するための
固定ケースである。実サイトへアクセスせず、保存済みページ資料の本文、HTML、画像、
商品値、認証情報をGit管理対象のリポジトリ、判断記録、完了報告へ写さない。資料は
`/.site-extraction-work/` 内のローカル識別子だけで指す。

Skill を作成または更新したら、次の全ケースを順に実行する。各ケースでは、Skill の
出力、実際に作成された判断記録、許可された範囲外の資料を読まなかったことを照合する。
`e2e/capture.spec.ts` や実行時のテストはこの照合の代わりにしない。登録候補ごとの実拡張の検証と
登録実装は `page-capture` が所有するが、Skill はその検証を登録提案の前提として要求する。

## 共通の照合方法

1. 入力不足では、固定順で最初に不足、空、または無効と判定した入力より前に読取済みの
   有効な入力だけを控える。後続入力、保存資料のローカル識別子、既存登録の識別子、利用条件の
   根拠は控えず、利用条件は `未判定` とする。この分岐では作業単位を作成しない。入力不足以外では、
   各入力、保存資料のローカル識別子、既存登録がある場合の識別子を控える。利用条件を `許可` と
   判断した後だけ、Git管理対象外の `/.site-extraction-work/<host>/<url-hash>/<run>/` を作業単位として
   作成する。
2. Skill の出力に、該当ケースで許されない候補、selector、保存資料の内容、商品値、
   認証情報、コード変更、登録または更新の提案が含まれないことを確認する。停止時は
   `対象`、`停止段階`、`理由`、`次に必要なもの` の四項目だけがこの順であることも確認する。
3. `許可` 後に作業単位を作成できるケースでは、表の「判断記録に必要な行」を取得前の同じ
   `decision.md` に含むことを確認する。行は項目名と安全な識別子・結論だけを持ち、ページ内容
   そのものを持たない。禁止・判断不能では判断記録も作業単位も作らないことを照合する。停止では
   `登録結果: 未登録`、登録可能な提案では `登録結果: 登録可能な候補を提案` を照合する。
4. 許可される読取範囲と実際の操作を照合する。禁止・判断不能では保存資料の読取がないこと、
   入力確認の停止では次の入力や保存資料を扱わないことを確認する。

作業単位は `host`、正規化URLの安定ハッシュ、UTC実行時刻で導出し、各単位に `page.html`、
`decision.md`、`candidate.md`、`verification.md` が用途別に残ることを照合する。同名単位が既に
存在する場合、または保存に失敗した場合は、既存・部分作成済みの単位を上書きも自動削除もせず、
登録または更新を変更しない停止結果を照合する。以前の作業領域が失われた場合は、以前の判断を
流用せず、利用条件の再確認と新しい単位での再取得から再開することを照合する。

## 固定ケース

| ケース | 入力と許可される読取範囲 | 期待する結果 | 判断記録に必要な行 |
| --- | --- | --- | --- |
| 規約禁止 | 有効な固定順の五入力と `禁止` を示す利用条件の根拠 URL・確認日。入力と利用条件の根拠だけを読む。保存資料、作業単位、判断記録は作らない。 | `対象: 対象サイトの利用条件`、`停止段階: 利用条件の判定` の停止結果を返す。候補、検証、登録、既存登録の更新を出さない。 | 判断記録なし。停止結果の理由と次に必要なもの、保存資料を読まないこと、未登録を照合する。 |
| 規約判断不能 | 有効な固定順の五入力と、許可・禁止を確定できない利用条件の根拠 URL・確認日。入力と利用条件の根拠だけを読む。保存資料、作業単位、判断記録は作らない。 | `対象: 対象サイトの利用条件`、`停止段階: 利用条件の判定` の停止結果を返す。候補、検証、登録、既存登録の更新を出さない。 | 判断記録なし。停止結果の理由と次に必要なもの、保存資料を読まないこと、未登録を照合する。 |
| 入力不足または項目欠損 | **入力不足:** 固定順で最初に不足、空、または無効と判定した入力より前の有効な入力だけを読む。後続入力、保存資料、利用条件の根拠は読まない。利用条件は `未判定` とし、作業単位は作らない。**項目欠損:** 許可済み判断を新規作業単位の `decision.md` に記録した後に、同じ単位の指定資料だけを読み、要求項目を直接検出できるかだけを確認する。 | 入力不足は `停止段階: 入力確認`、項目欠損は `停止段階: 要求項目の確認` の停止結果を返す。いずれも登録可能な候補、コード変更、検証、登録を出さない。 | **入力不足:** 完了記録に読取済みの先行入力だけと `利用条件: 未判定` を記し、`作業単位: 作成なし（後続入力を未読）` が出力で観測でき、作業単位がないことを確認する。**項目欠損:** 新規作業単位の `decision.md` には、共通の入力・資料識別子・判断情報に加え、`停止段階`、`不足または欠損項目`、`停止理由`、`次に必要なもの`、`登録結果: 未登録` を含める。 |
| 未対応属性 | 許可済み判断を新規作業単位の `decision.md` に記録した後に、同じ単位の指定資料で、対象カテゴリの既存 `CATEGORY_ATTRIBUTES` にない属性キーを確認する。入力、利用条件の根拠、指定保存資料だけを読む。 | `停止段階: 候補の適合確認` の停止結果を返す。候補全体を登録対象にせず、共通項目への代替、推測、コード変更、検証、登録を出さない。 | 共通の入力・資料識別子・判断情報に加え、`停止段階: 候補の適合確認`、`対象: 未対応属性`、`停止理由`、`次に必要なもの: 対象カテゴリに既に定義された属性キー`、`登録結果: 未登録` を同じ `decision.md` に含める。 |
| 未明記値 | 許可済み判断を新規作業単位の `decision.md` に記録した後に、同じ単位の指定資料で、取得したい項目または許可属性の値が明記されていないことを確認する。入力、利用条件の根拠、指定保存資料だけを読む。 | `停止段階: 候補の適合確認` の停止結果を返す。候補全体を登録対象にせず、共通項目への代替、推測、コード変更、検証、登録を出さない。 | 共通の入力・資料識別子・判断情報に加え、`停止段階: 候補の適合確認`、`対象: 未明記値`、`停止理由`、`次に必要なもの: 値が明記された保存済みページ資料`、`登録結果: 未登録` を同じ `decision.md` に含める。 |
| 初回登録 | 許可済み判断と記録、完全な固定順の五入力、共通項目または対象カテゴリで既に許可された属性を明記する保存資料。入力、利用条件の根拠、指定保存資料だけを読む。 | 指定項目を直接読む selector、安定した由来ラベル、期待する `site-specific` 候補、対象カテゴリと許可属性キー・元表記を未確認の候補編集へ渡す提案、固有規則が値を返さない場合の汎用フォールバック、実拡張検証の追加を提案する。候補追加前の汎用シナリオ記録、実在データを含まない fixture による実拡張検証、`pnpm validate` の既存汎用シナリオ維持を確認できるまで登録・更新は実行しない。 | `対象ページ URL`、`製品カテゴリ`、`取得したい項目`、`保存資料識別子`、`判断: 許可`、`根拠 URL`、`確認日`、`候補: 検証対象`、`汎用シナリオ: 追加前に記録`、`実拡張検証結果`、`検証結果`、`登録結果: 登録可能な候補を提案`。selector、期待値、ページ内容、商品値は記録しない。 |
| 再生成失敗 | 既存の検証済み登録の安全な識別子、以前の判断記録の識別子、許可済み判断、完全な固定順の五入力、新しい保存資料、検証に失敗する候補。入力、利用条件の根拠、指定新資料、既存登録の識別子だけを読む。 | 初回と同じ規約確認と検証を行った上で、失敗の停止結果を返す。既存登録の差分、未確認候補による置換、登録または更新を出さない。 | `再生成日時`、`保存資料識別子`、`判断: 許可`、`根拠 URL`、`確認日`、`既存登録: 保持`、`失敗段階`、`停止理由`、`次に必要なもの`、`登録結果: 未登録`。 |
| 作業単位の衝突または保存失敗 | 許可済み判断、完全な固定順の五入力、導出済み作業単位の最終パスが存在する、または `decision.md`、`page.html`、`candidate.md`、`verification.md` のいずれかの新規保存が失敗する状態。既存単位の内容は読取・変更しない。 | `停止段階: ローカル作業領域` の停止結果を返す。既存または部分作成済み単位の上書き、自動削除、登録、既存登録の更新を出さない。 | 新規単位の安全な識別子、失敗段階、停止理由、次に必要なもの、`登録結果: 未登録`。既存単位には変更がないことを確認する。 |
| 作業領域の消失 | 以前の作業単位または作業領域が存在しない状態で、完全な固定順の五入力と再確認する利用条件の根拠 URL・確認日を与える。以前の判断、資料、候補、検証結果は読まない。 | 以前の判断を流用せず、利用条件を再確認する。`許可` のときだけ新しい作業単位を作成して再取得から再開し、それ以外は未登録で停止する。 | 新しい `decision.md` に再確認した判断、根拠 URL、確認日、対象URLを残す。以前の単位を再作成、上書き、または削除しないことを確認する。 |

## 登録候補ごとの実拡張照合

初回登録または再生成で登録・更新の候補を提案する前に、`page-capture` が所有する既存の
`e2e/capture.spec.ts` を、実在データを含まない fixture で拡張して実行する。Skill の固定ケースと
この照合はどちらも必要であり、片方で他方を代用しない。fixture には実サイト由来の本文、HTML、画像、
商品値、認証情報を入れない。

1. 候補追加前に、同じ fixture の既存汎用抽出をビルド済み拡張と拡張アイコン操作から実行し、安全なシナリオ識別子と結果だけを判断記録に残す。
2. 候補追加後は、指定項目が `site-specific` の由来と安定した `sourceLabel` を持ち、結果と candidate-capture-handoff の分類・属性が未確認のままであることを確認する。属性がある場合は許可キーだけを確認し、`confirmed` への昇格がないことを確認する。
3. 固有 selector が値を返さない状態では、候補を追加せず例外を外へ出さず、既存の JSON-LD、meta、構造 collector の汎用結果が残ることを確認する。資料に明記されない値が候補または handoff にないことも確認する。
4. `pnpm validate` で、記録した汎用シナリオを含む既存シナリオが維持されることを確認する。保存資料の指定項目検証とこの全照合が合格した場合だけ、判断記録に `実拡張検証結果: 合格` と `登録結果: 登録可能な候補を提案` を残せる。

再生成では、上の全照合を利用条件の再判定後に繰り返す。一つでも不合格なら、既存の検証済み登録を保持し、
判断記録へ `再生成日時`、`保存資料識別子`、`既存登録: 保持`、`失敗段階`、`停止理由`、`次に必要なもの`、
`登録結果: 未登録` を追記する。更新差分、未確認候補による置換、登録または更新の提案を出してはならない。

## 完了記録

全固定ケースの後、ケースごとに次の形式で完了記録を残す。実在の URL、資料内容、
商品値、selector は書かない。

```text
ケース: <固定ケース表のケース名>
許可読取範囲: <読んだ入力と根拠・資料識別子だけ>
Skill出力: <停止段階と未登録 | 登録可能な候補を提案>
判断記録照合: <必要な行がそろう | 無効な記録先のため記録なしを確認>
非読取照合: <保存資料を読まない | 後続入力を読まない | 指定資料だけを読む>
登録可否: <未登録 | 登録可能な候補を提案>
結果: 合格 | 不合格
```

一つでも期待結果、判断記録、読取範囲が一致しなければ `結果: 不合格` とし、
登録可能な候補、登録、既存登録の置換へ進まない。初回登録の `合格` は Skill 手順の
登録可能性だけを示し、`page-capture` の実拡張検証または登録済みを意味しない。
