# 機能要件（v0.4.0 からのリバース）

画面に現れない規則・データ構造・判定ロジックを記述する。
画面上の見え方は `screens.md`、目的と背景は `requirements.md` を参照。

---

## 1. データモデル

### 1.1 全体構造

```
LocalDataRoot
├── schemaVersion, revision
├── projects[]        プロジェクト
├── candidateParts[]  パーツ候補（プロジェクトに直接所属）
└── currentBuilds[]   現在構成（プロジェクトごとに 0..1）
```

プロジェクトが構成検討の単位であり、パーツ候補はプロジェクトへ直接所属する。
プロジェクトを削除すると、所属するパーツ候補と現在構成も削除される。

### 1.2 値の二層構造

自動取得された**元表記**と、利用者が確認・修正した**確定値**を分離して保持する。

```
SourcedValue<T> = { original: string | null, confirmed?: T }
```

- `original`: 取得元ページでの表記そのまま。取得できなければ `null`
- `confirmed`: 利用者が確認・確定した正規化値。未確認なら不在

**互換性判定は `confirmed` のみを見る。** `original` があるだけでは判定に使わない。
これが「不確かな情報から互換性を断定しない」を保証する仕組みである。

### 1.3 カテゴリと属性

カテゴリは 12 種: `cpu` `cpu-cooler` `motherboard` `memory` `gpu` `storage`
`power-supply` `case` `case-fan` `expansion-card` `other` `uncategorized`

| カテゴリ | 正規化属性 | 型 |
|---|---|---|
| cpu | socket | 文字列 |
| cpu-cooler | supportedSockets | 文字列配列 |
| motherboard | socket / memoryStandard / formFactor | 文字列 |
| memory | memoryStandard | 文字列 |
| case | supportedMotherboardFormFactors / supportedPowerSupplyFormFactors | 文字列配列 |
| power-supply | formFactor | 文字列 |
| 上記以外 | なし | — |

ソケット名・メモリ規格は**固定値リストを持たない**（新規格が随時出るため自由文字列）。
フォームファクタのみ安定した既知値を持つ:
- マザーボード: `E-ATX` `ATX` `Micro-ATX` `Mini-ITX`
- 電源: `ATX` `SFX` `SFX-L`

一覧値の属性には自由入力の逃げ道を用意する。

### 1.4 価格と通貨

`MoneyValue = { amount: number, currency: string }`

通貨は取得元ページの表記を尊重する。**取得できなかった場合に推測しない。**
未確定は不明のまま保持する。為替換算・レート取得は行わない。

### 1.5 ソース（取得元）

一つのパーツは複数のソースを持つ。

| 項目 | 内容 |
|---|---|
| url | 取得元 URL（http/https のみ） |
| kind | `retail`（販売ページ）/ `manufacturer`（メーカー商品紹介） |
| capturedAt | 取得日時（UTC） |
| price | そのソースでの価格 |
| primary | プライマリ指定（パーツごとに必ず 1 つ） |

- プライマリの価格がパーツの代表価格になる
- プライマリを削除するには、先に代わりのソースを指定する必要がある
- ソースからは元ページを新規タブで開ける（再訪導線）

## 2. 取り込み（Capture）

### 2.1 起動と権限

利用者が拡張アイコンを操作した時のみ起動する。ページ読み取り権限はその都度取得し、
常時保持しない。取り込み中に対象タブが遷移・更新された場合は中断する。

新しい起動操作は、古い失敗状態や保持中の結果を置き換える（起動世代の概念）。

### 2.2 抽出の優先順位

サイト固有ロジックを持たず、以下の汎用手掛かりのみを使う。

| 優先 | 出典 | 表示名 |
|---|---|---|
| 1 | JSON-LD (schema.org Product) | 構造化データ |
| 2 | OpenGraph / meta | メタ情報 |
| 3 | 見出し (h1 等) | 見出し |
| 4 | パンくず | パンくず |
| 5 | 表 (table) | 表 |
| 6 | 定義リスト (dl) | 定義リスト |
| — | ドメイン対応表 | メーカー公式ドメイン |

抽出結果には必ず**出典と元表記**を添える。

### 2.3 検証と棄却

抽出値は項目ごとに検証し、通らなければ棄却して理由を残す。

| 理由 | 意味 |
|---|---|
| empty | 値が空 |
| tooLong | 値が長すぎる |
| controlCharacters | 制御文字を含む |
| invalidFormat | 形式が正しくない |
| unresolvable | 値を解釈できない |

棄却された項目は「取り込めなかった項目」として利用者に提示する。**黙って捨てない。**

### 2.4 カテゴリ推定

商品名・パンくず等からカテゴリを推定する。推定できた場合は編集フォームの
初期選択にする（確定はしない）。推定できない場合は `uncategorized` とする。
ロケール固有のキーワード辞書は、汎用エンジンへの**加算的な最適化**として持つ。

### 2.5 失敗の分類

`permission-lost` / `restricted-page` / `tab-changed` / `injection-failed` /
`invalid-payload` / `no-candidate`

いずれも理由と次の一手（再実行／手入力で続ける）を提示する。

### 2.6 プロジェクト未解決時の引き渡し

保存先プロジェクトが未選択・利用不能の場合、**抽出結果を保持したまま**
プロジェクト選択／作成を促す。解決後は同じ内容で編集を再開する。
再取り込みは発生させない。

## 3. 重複判定（Duplicate Merge）

保存時、同一プロジェクト内の既存パーツと商品同一性を照合する。

| 根拠 | 確信度 |
|---|---|
| 型番が一致 | 高 |
| メーカーと商品名が一致 | 補助 |

一致候補がある場合、「新しいパーツとして保存」と「選択したパーツへ統合」を
**排他選択**として提示する。統合は既存パーツへソースを追加する形で行う。
同一 URL の再取り込みは、新規作成ではなく既存ソースの更新として扱う。

照合中に対象が更新された場合は競合として再照合を促し、既存パーツは変更しない。

---

## 4. 現在構成（Current Build）

プロジェクトごとに 0 個または 1 個。採用パーツと数量の集合。

- 数量は正整数のみ。不正値は保存しない
- 同一カテゴリに複数採用できる（メモリ、ストレージ、ケースファン等）
- 候補を削除すると、現在構成からも解除される
- プロジェクト切替時、未保存の数量入力は確認を挟む
- 強制的なプロジェクト変更では未保存入力を隔離保持し、保存対象にしない

## 5. 互換性判定（Compatibility）

### 5.1 判定の入力

**現在構成に採用されているパーツの `confirmed` 値のみ**を入力とする。
`original` しかない値、未採用の候補は判定に使わない。

### 5.2 ルール

| ルール ID | 左 | 右 | 判定 |
|---|---|---|---|
| cpu-motherboard-socket | CPU.socket | motherboard.socket | 等値 |
| motherboard-memory-ddr | motherboard.memoryStandard | memory.memoryStandard | 等値 |
| cooler-cpu-socket | CPU.socket | cooler.supportedSockets | 包含 |
| case-motherboard-form-factor | motherboard.formFactor | case.supportedMotherboardFormFactors | 包含 |
| case-psu-form-factor | psu.formFactor | case.supportedPowerSupplyFormFactors | 包含 |

### 5.3 判定結果

各ルールは 3 値のいずれかを返し、必ず根拠を伴う。

| 結果 | 根拠の語彙 |
|---|---|
| 一致 | 規格が一致している / 対応範囲に含まれる |
| 不一致 | 規格が一致していない / 対応範囲に含まれない |
| 情報不足 | 必要な確認済み情報が不足している |

情報不足の場合は、不足の内訳（対象カテゴリが未選択なのか、
選択済みだが値が未確認なのか）を側ごとに示す。

### 5.4 総合判定

- 1 つでも不一致があれば **互換性なし**
- 不一致がなく、すべて一致していれば **互換性あり**
- 不一致がなく、情報不足を含めば **判定不能**

**情報不足を不整合と誤認しない。** これは絶対条件である。

## 6. 永続化（Persistence）

### 6.1 保存先と単位

`chrome.storage.local` の単一ルートオブジェクトとして保持する。
書き込みは**ルート単位の原子的置換**で行う。部分更新はしない。

### 6.2 保証すべき性質

| 性質 | 内容 |
|---|---|
| 原子性 | 書き込みは全部成功するか全部失敗するか |
| 単一書き込み権限 | 同時書き込みを避ける |
| スキーマ検証 | 読み込み時に構造を検証し、非対応形式を検出する |
| 破損検出 | 破損データを検出し、既存データを壊さずに利用者へ通知する |
| 移行 | `schemaVersion` に基づく移行経路を持つ |

> 注: v0.4.0 の実装はこの表の性質に対して過剰である
> （23 ファイル・トランザクションランナー・回復制御・参照修復ポリシー等）。
> 再実装では**この表の性質を満たす最小の実装**にとどめる。

### 6.3 エラーの利用者提示

保存領域が使えない / データが破損している / 対応しない形式である /
対象が見つからない の 4 分類を、それぞれ次の一手とともに提示する。
いずれの場合も**既存データを変更しない**ことを明示する。

データが破損した場合の復旧手段は持たない（バックアップ機能を持たないため）。
検出して利用者へ知らせるところまでを責務とする。

## 7. 国際化（i18n）

**Chrome 標準の拡張 i18n 機構をそのまま使う。独自の文言解決機構は持たない。**

### 7.1 仕組み

| 要素 | 内容 |
|---|---|
| 文言の置き場 | `_locales/ja/messages.json` / `_locales/en/messages.json` |
| 既定ロケール | manifest の `default_locale` に `ja` |
| HTML / CSS / manifest | `__MSG_key__` 置換 |
| JS | `chrome.i18n.getMessage(key, substitutions)` |
| プレースホルダ | `messages.json` の `placeholders` を使う |

### 7.2 表示言語の決定

表示言語は **ブラウザの UI 言語**（`chrome.i18n.getUILanguage()`）で決まる。
拡張の中から実行時に切り替えることはできず、**そのための機構も持たない**。
アプリ内の言語設定は存在しない。

対応ロケールに一致しない UI 言語では `default_locale` の `en` に落ちる。
国・言語に依存しない汎用エンジンという方針から、フォールバックは `ja` ではなく `en` とする。

### 7.3 文言定義の規則

- **パラメータを含む文言は、断片の連結ではなく完結した 1 文として定義する。**
  `placeholders` を使い、語順が言語で変わっても壊れないようにする
  （v0.4.0 の互換性画面の連結崩れはこれを守らなかったことが原因。`changes.md` C-2-1）
- UI 文言をコード中へ直接埋め込まない
- ja / en は同じキー集合を持つ

### 7.4 挙動の不変性

**言語によって挙動は変わらない。** これは E2E で固定すべき性質である。

検証は、ブラウザ起動オプション `--lang` を変えた 2 つのコンテキストで
同一シナリオを実行して行う（`--lang=ja` / `--lang=en-US` が
`_locales/ja` / `_locales/en` を解決することは v0.4.0 ビルドで実測確認済み）。
アプリ内トグルを使った検証も、合成ハーネスも使わない。

### 7.5 ロケール固有データ

ロケール固有の取り込み支援（日本語価格表記のパース等）は**翻訳ではない**。
`_locales` ではなくロケール別データとして持ち、
他ロケールの動作を妨げない範囲で加算的に追加する。

### 7.6 対象外

ロケール別の日付・数値・通貨フォーマット / 通貨の自動換算 / 3 言語目以降。

## 8. 動作環境の制約

| 項目 | 制約 |
|---|---|
| Manifest | V3 |
| Chrome | 116 以降 |
| CSP | インライン実行・eval 不可。スキーマ検証も CSP 適合が必要 |
| 権限 | ページ読み取りは利用者操作の都度のみ |
| 通信 | 利用者が明示操作したページの取得以外に外部通信しない |
| テストデータ | 実在の商品・サイトを使わず架空フィクスチャのみ |
