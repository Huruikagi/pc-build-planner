# 画面要件（v0.4.0 からのリバース）

本書は v0.4.0 の実画面を操作して逆算した**現状の画面構成**である。
本書は「v0.4.0 は現状こうである」の忠実な記録であり、意図的に更新しない。
再実装で変える点は `changes.md`、決定した見た目はデザインキャンバスが持つ。

**再実装の入力は次の 3 つを重ねて読む。**

| | 役割 |
|---|---|
| 本書（`screens.md`） | v0.4.0 が何をどう見せていたかの記録 |
| `changes.md` | そこから意図的に変える点（C-1〜C-5） |
| デザインキャンバス | 決定した具体レイアウト・配色・アイコン |

本書と `changes.md` が矛盾する箇所は、`changes.md` が優先する。

- 表示面: Chrome サイドパネル（幅 ~400px の縦長 1 カラム）
- 出典: `v0.4.0` を実ビルドし、実データを投入して全画面を撮影・DOM 走査

---

## 0. 画面の全体構造

```
┌─ サイドパネル ──────────────────┐
│ [ナビゲーション]  3つのアイコンタブ         │
├──────────────────────────────┤
│ [共通スロット]    現在のプロジェクト セレクタ  │  ← 全画面に常駐
├──────────────────────────────┤
│ [機能スロット]    選択中の機能の本体          │
└──────────────────────────────┘
```

### 常設ナビゲーション（3 面）

| 順 | 画面 | 役割 |
|---|---|---|
| 1 | パーツ管理 | 候補の一覧・追加・編集・削除（既定表示） |
| 2 | 現在構成 | 採用パーツと数量の管理 |
| 3 | 互換性確認 | 規格整合性の評価結果 |

### 一時表示面（ナビゲーションに出ない）

| 面 | 起動契機 | 終了契機 |
|---|---|---|
| 取り込み | 拡張アイコンの操作 | 完了・失敗の解消・対象タブの遷移 |
| 価格更新 | 候補からの明示操作 | 完了・取消・対象タブの遷移 |

一時表示面は起動中だけ機能スロットを占有し、常設ナビゲーションには現れない。

### 共通プロジェクトセレクタ

全画面の上部に常駐する。現在のプロジェクトを選び、選択は全画面で共有される。
未保存の編集がある状態で切り替えようとした場合は確認を挟む
（保存して切替／破棄して切替／切替を取消）。

状態は 3 つ: `ready`（選択済み）/ `empty`（プロジェクトなし）/ `unavailable`（読み込めない）。
`empty` と `unavailable` では各画面は作業不能状態を表示し、再試行導線を出す。

## 1. パーツ管理

既定で表示される画面。上から順に以下が縦に並ぶ。

1. **プロジェクト操作**（現在プロジェクト名 / 名前を変更 / 削除）
2. **プロジェクト作成フォーム**（新しいプロジェクト名 + 作成ボタン）
3. **カテゴリフィルタ**（13 個のチップ: すべて / CPU / CPUクーラー / マザーボード / メモリ / GPU / ストレージ / 電源 / ケース / ケースファン / 拡張カード / その他 / 未分類）
4. **パーツを追加** ボタン
5. **パーツ一覧**（カード形式）
6. **パーツ編集フォーム**（追加・編集時のみ、一覧の下に展開）

> この 1・2 の位置取りが、再実装で変更する対象。詳細は `changes.md`。

### パーツカードの表示項目
商品名（見出し） / カテゴリ / メーカー / 型番 / 価格 / プライマリ
未入力の項目は「未入力」とグレーで表示し、1 つでもあればカード下部に
「未入力の項目があります」を出す。操作は「編集」「削除」。

### パーツ編集フォーム

| 区分 | 項目 |
|---|---|
| 基本 | 商品名（必須）/ メーカー / 型番（「型番なし」で不在を確定できる）/ カテゴリ（選択） |
| カテゴリ別属性 | 選択カテゴリに応じて動的に切り替わる（下表） |
| ソース | 取得元 URL / 取得日時 / 種別 / 価格 / プライマリ指定。手入力で複数追加・編集・削除可 |
| 取得元表記 | 自動取得時の元表記（現状は生 JSON のテキストエリア） |

カテゴリ別属性:

| カテゴリ | 属性 |
|---|---|
| CPU | ソケット |
| CPUクーラー | 対応ソケット（複数） |
| マザーボード | ソケット / メモリ規格 / フォームファクター |
| メモリ | メモリ規格 |
| ケース | 対応マザーボード規格 / 対応電源規格（複数） |
| 電源 | フォームファクター |
| その他 | 属性なし |

複数選ぶ規格（対応マザーボード規格 / 対応電源規格）は既知の規格を選択式
（チップ）で入力する。既知の一覧に無い値には「その他（自由入力）」の
逃げ道があり、選択肢を強制しない。

### 削除確認
プロジェクト削除は「所属するパーツも削除される」ことを明示する。
未保存の編集がある場合はその旨も警告する。パーツ削除は対象名を提示する。

## 2. 現在構成

1. **カテゴリ別サマリ**（カテゴリ名 + 採用中パーツ名 ×数量、未採用は「未選択」）
2. **候補一覧**（採用／解除、数量入力 + 数量を確定）

数量は正整数。不正値はエラー表示し保存しない。
未保存の数量がある状態でプロジェクト切替を試みると確認を挟む。
強制的にプロジェクトが変わった場合、未保存入力は隔離して保持し、
「新しいプロジェクトには保存されない」ことを明示して破棄導線を出す。

空状態: パーツなし →「パーツがありません」/ 構成なし →「現在構成がありません」

---

## 3. 互換性確認

現在構成に対する評価結果を 1 枚で表示する。

**総合判定**: 互換性あり / 互換性なし / 判定不能（情報不足）
**個別判定**: ルールごとに 判定・対象パーツ・根拠 を列挙する

評価ルール（5 種）:

| ルール | 左 | 右 | 判定内容 |
|---|---|---|---|
| CPUソケット | CPU | マザーボード | 値の一致 |
| メモリ規格 | マザーボード | メモリ | 値の一致 |
| CPUクーラー対応ソケット | CPU | CPUクーラー | 対応範囲への包含 |
| ケース対応フォームファクタ | マザーボード | ケース | 対応範囲への包含 |
| ケース対応電源規格 | 電源 | ケース | 対応範囲への包含 |

根拠の語彙: 規格が一致している / 一致していない / 対応範囲に含まれる /
含まれない / 必要な確認済み情報が不足している

情報不足は不整合と区別し、不足している側（未選択なのか、値が未確認なのか）を明示する。

状態: 評価待ち / 読み込み中 / 評価結果 / プロジェクトなし /
プロジェクト情報を利用できません / 判定対象なし / 評価失敗

## 4. 取り込み（一時表示面）

拡張アイコンの操作で機能スロットに現れる。状態遷移は以下。

```
待機 ──[取り込みを開始]──> 取り込み中 ──┬─> 結果あり ──> パーツ編集へ引き渡し
                                    └─> 失敗 ──> 再実行 / 手入力で続ける
```

**待機**: 「拡張のアイコンから取り込みを開始してください。」+ 取り込みを開始
**取り込み中**: 「ページを取り込んでいます…」
**成功**: 抽出結果をパーツ編集フォームへ引き渡し、パーツ管理画面へ遷移する
**失敗**: 理由別の文言 + 再実行 / 手入力で続ける

取得できた項目には出典（構造化データ / メタ情報 / 見出し / パンくず / 表 /
定義リスト / メーカー公式ドメイン）と元表記を添える。
取得できなかった項目は理由（値が空 / 長すぎ / 制御文字 / 形式不正 / 解釈不能）とともに一覧する。
カテゴリは推定を試み、推定できた場合は編集フォームの初期選択にする。推定できない場合は未分類。

失敗理由の区別: 権限失効 / 読み取り対象外ページ / 取り込み中のページ遷移 /
読み取り失敗 / 内容を解釈できない / 商品情報を自動取得できない

**プロジェクト未選択時**: 抽出結果は保持したまま「続行するにはプロジェクトを選んでください」
を表示し、既存から選ぶ／新規作成する導線を出す。解決後は抽出内容のまま編集を再開する。
再取り込みは発生させない。

---

## 5. 重複確認（パーツ編集内のサブ面）

保存時に既存パーツとの一致が検出された場合に現れる。

一致候補ごとに メーカー / 型番 / カテゴリ / 確信度（高・補助）/
一致根拠（型番が一致 / メーカーと商品名が一致）を提示する。
選択肢は「新しいパーツとして保存」「選択したパーツへ統合」の排他 2 択。

---

## 6. 価格更新（一時表示面）

保存済みパーツのプライマリソースから現在価格を取得し、単一コミットで更新する。
対象タブが遷移した場合は面を終了し、保存データは変更しない。

---

## 7. 全画面に共通する原則

1. **欠損は正常状態**。未入力・未分類・未確認を異常として扱わず、そのまま保存・表示する。
2. **自動取得値と確認済み値を分離する**。元表記を保持し、利用者が確認した値と区別する。
3. **破壊的操作は必ず確認を挟む**。削除、およびプロジェクト切替時の未保存編集。
4. **失敗は理由と次の一手を示す**。汎用エラーで終わらせない。
5. **未保存の入力を失わせない**。エラー時も切替時も入力は保持する。
