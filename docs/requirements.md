# pc-build-planner MVP 要求仕様

## 1. 文書の位置づけ

この文書は、個人利用向けMVPとして開発する `pc-build-planner` Chrome拡張の要求をまとめる。

長期的なプロダクト像は `project-overview.md` に記載する。この文書と長期構想が異なる場合、MVPの実装範囲についてはこの文書を優先する。

## 2. 解決したい課題

自作PCの構成を検討するとき、Web上で見つけた商品について、カテゴリ、メーカー、商品名、型番、URL、主要スペックなどをスプレッドシートへ手作業で転記するのが面倒である。

MVPは、閲覧中の商品ページから候補パーツを取り込み、PC構成として整理するまでの手間を減らす。

## 3. 対象ユーザー

最初の対象ユーザーは開発者自身とする。

- 自作PCの組み立て経験がある
- Web上の複数サイトでパーツを探す
- 候補を比較しながら次の構成やアップグレードを検討する
- 初心者向けの組み立て手順より、候補の整理と基本的な互換性確認を必要としている

## 4. MVPの提供形態

MVPは、PC版Chromeで動作するローカルファーストのChrome拡張とする。

- Webアプリとバックエンドサーバーは持たない
- ユーザーアカウントを持たない
- 中央の商品データベースを持たない
- 端末間同期を行わない
- 商品情報、プロジェクト、構成情報はローカルに保存する
- JSONによるバックアップと復元を提供する
- 当面はChrome Web Storeへ公開せず、開発者の手元で未パッケージ拡張として利用する

## 5. 基本概念

### 5.1 プロジェクト

プロジェクトは、1つのPC構成の検討単位である。MVPではプロジェクトと構成を別エンティティに分けない。

プロジェクトは次の情報を持つ。

- プロジェクト名
- プロジェクト内の候補パーツ
- 各カテゴリで現在の構成に選択されているパーツ

AM4案とAM5案のように前提が大きく異なる案は、別プロジェクトとして管理する。MVPでは、1つのプロジェクト内に複数の構成案を保存しない。

### 5.2 候補パーツ

商品は、取り込み操作を行ったプロジェクトへ直接所属する。MVPでは、プロジェクトを横断するユーザー共通パーツライブラリを設けない。

同一カテゴリに複数の商品を登録できる。たとえば、CPU候補として Ryzen 7 8700G と Ryzen 7 9700X を同じプロジェクトに保持できる。

### 5.3 現在の構成

ユーザーは、プロジェクト内の候補から現在の構成に使用する商品を選択する。

互換性チェックは、候補全体の総当たりではなく、現在の構成に選択されているパーツ間だけを対象とする。

## 6. 基本ユーザーフロー

```text
プロジェクトを作成する
        ↓
Chromeで商品ページを開く
        ↓
拡張を明示的に実行する
        ↓
表示中のページから商品情報をローカルで抽出する
        ↓
抽出結果を確認・修正する
        ↓
プロジェクトの候補パーツへ登録する
        ↓
各カテゴリから現在の構成に使うパーツを選択する
        ↓
選択されたパーツ間の互換性を確認する
```

## 7. 商品取り込み

### 7.1 実行条件

- ユーザーが拡張を明示的に実行したときだけ、現在表示中のタブを読み取る
- 常時監視、定期巡回、一括取得は行わない
- サーバーから対象サイトへアクセスしない
- 生のHTMLを永続保存しない

Chrome権限は、可能な限り `activeTab` と `scripting` を利用し、恒久的な全サイトアクセスを要求しない。

### 7.2 抽出方法

MVPではAIおよび外部AI APIを使用しない。次の優先順位で拡張内の抽出を行う。

1. JSON-LDなどの構造化データ
2. OGP、ページタイトル、パンくずなどの汎用情報
3. HTMLの表や定義リストからの汎用的な項目名・値の抽出
4. 共通の項目名辞書によるカテゴリと主要スペックの候補化
5. ユーザーによる確認と手動補正

抽出に失敗しても登録処理を中断しない。登録先プロジェクトと商品ページURLがあれば、取得できた項目だけで候補として保存できる。商品名を取得できない場合は、ページタイトルまたはURLを一覧表示に使用する。

カテゴリを特定できない商品は「未分類」として保存する。未分類の商品は現在の構成へ選択できず、互換性判定の対象にもならない。ユーザーが登録後に情報を編集してカテゴリを設定すると、構成の候補として利用できる。

### 7.3 初期対応サイト

- MVPでは特定サイトへの正式対応を前提とせず、汎用抽出を最初に実装する
- 価格.com、通販サイト、メーカー公式サイトなど、構造の異なるページで汎用抽出の取得率を検証する
- サイト別アダプターは、汎用抽出で不足する項目と必要性を確認してから追加する

価格.com向けの専用アダプターはMVPおよび公開リポジトリに含めない。将来追加を検討する場合は、カカクコムへの事前確認と、必要に応じた専門家への相談を行う。確認前に個人用PoCを作る場合も、公開リポジトリとは分離する。

抽出処理は、汎用抽出器とサイト別アダプターを分離できる構造にする。価格.com向けアダプターを除外しても、汎用的な商品登録、プロジェクト管理、構成管理、互換性確認が動作することを前提とする。

### 7.4 商品情報

商品は、少なくとも次の項目を保持できる。

- 商品カテゴリ
- メーカー
- 商品名
- 型番
- 商品ページURL
- 主要スペック
- 価格
- 備考
- 取得元サイト
- 取得日時
- 自動抽出された元の表記
- ユーザーが確認・修正した値

各項目は欠損を許容する。互換性判定に必要な項目が不足している場合は、判定不能として扱う。

登録済みの商品は、すべてのユーザー編集可能項目を後から修正できる。自動抽出に成功した商品についても、ユーザーが確認・補正できる。

### 7.5 確認・手動修正フォーム

手動修正フォームは抽出失敗時だけの代替手段ではなく、MVPの主要な登録導線とする。

フォームは、商品ページ上で素早く保存するための「簡易表示」と、商品情報と互換性属性を整えるための「詳細編集」に分ける。

#### 7.5.1 簡易表示

サイドパネルで商品を取り込んだ直後に表示する。

- 抽出できた値をあらかじめ入力した状態で表示する
- 登録先プロジェクト、商品名、メーカー、型番、カテゴリ、価格を表示・編集できる
- URLと取得元サイトを確認できる
- 必須項目は登録先プロジェクトと商品ページURLだけとする
- 「未分類で保存」「候補に追加」「詳細を編集」を選択できる
- 未入力や判定不能な項目があっても保存できる

#### 7.5.2 詳細編集

保存前の簡易表示および保存後の候補一覧から開ける。

- URL、商品名、メーカー、型番、カテゴリ、価格、備考を編集できる
- 取得元サイト、取得日時、URLを確認できる
- カテゴリを選択すると、そのカテゴリの互換性判定に必要な項目を表示する
- 抽出した元の項目名と値を参照しながら、正規化後の値を選択・入力できる
- 未分類からカテゴリを設定した場合は、対応する互換性項目を続けて入力できる
- 入力済みの共通項目は、カテゴリを変更しても失わない
- 登録済みの商品は、候補一覧からいつでも再編集できる

MVPでカテゴリ別に表示する互換性項目は次のとおり。

| カテゴリ | 互換性項目 |
| --- | --- |
| CPU | CPUソケット |
| CPUクーラー | 対応CPUソケット（複数選択） |
| マザーボード | CPUソケット、メモリ規格、フォームファクタ |
| メモリ | DDR規格 |
| ケース | 対応マザーボードフォームファクタ、対応電源フォームファクタ（いずれも複数選択） |
| 電源 | 電源フォームファクタ |
| GPU、ストレージ、ケースファン、拡張カード、その他 | MVPでは互換性項目なし |
| 未分類 | 互換性項目を表示しない |

商品の数量は商品情報ではなく構成内での使用数であるため、このフォームでは扱わない。数量は候補を現在の構成へ選択するときに指定する。

商品画像はMVPでは取得、保存、表示しない。

### 7.6 価格

- 商品登録時に取得できた価格を保存する
- 価格を取得した日時を保存する
- 取得できない場合は未入力を許容する
- 保存した価格はユーザーが手動で修正できる
- MVPでは価格履歴を持たず、商品ごとに1つの価格だけを保持する
- 購入価格は登録時価格と区別して管理せず、将来の拡張候補とする

## 8. パーツカテゴリと選択数

候補パーツはカテゴリ別に管理する。

初期カテゴリは次を想定する。

- CPU
- CPUクーラー
- マザーボード
- メモリ
- GPU
- ストレージ
- 電源
- ケース
- ケースファン
- 拡張カード
- その他
- 未分類

現在の構成では、カテゴリに応じて単一または複数の商品を選択できる。

- 単一選択を基本とするカテゴリ: CPU、CPUクーラー、マザーボード、電源、ケース
- 複数選択を許可するカテゴリ: メモリ、GPU、ストレージ、ケースファン、拡張カード、その他

複数選択カテゴリでは、異なる商品を複数選択できるほか、同一商品の数量を指定できる。

未分類カテゴリは候補の一時保存とブックマークに使用し、現在の構成には選択できない。

## 9. 互換性チェック

互換性チェックは、現在の構成に選択されているパーツと、ユーザーが確認した正規化済み属性を使用する。

判定結果は次のいずれかとする。

- 互換性あり
- 互換性なし
- 注意事項あり
- 情報不足で判定不能

MVPでは次の互換性を判定する。

- CPUとマザーボードのソケット
- マザーボードとメモリのDDR規格
- CPUクーラーとCPUソケット
- ケースとマザーボードのフォームファクタ
- ケースと電源のフォームファクタ

GPU長、CPUクーラー高、電源容量、コネクター、M.2、BIOSバージョンなどの複雑または不確実な判定は初期候補に含めない。

## 10. ローカルデータ

- プロジェクトと商品情報はChrome拡張のローカル領域へ保存する
- 商品ページの生HTMLは保存しない
- 取得した商品情報を共通カタログとして再配布しない
- JSONファイルへ全データをエクスポートできる
- JSONファイルからデータを復元できる
- 拡張を削除するとローカルデータが失われる可能性をユーザーへ明示する
- バックアップと復元はユーザーが管理画面から手動で実行する
- 自動バックアップと定期的なバックアップ通知はMVPでは行わない

将来Webアプリ、モバイルアプリ、同期機能を追加する場合も、MVPのエクスポート形式から移行できるデータモデルを維持する。

## 11. UIの役割

### 11.1 サイドパネル

- 表示中の商品情報を抽出する
- 抽出結果を確認・修正する
- 取得できた情報が少なくても、URLを未分類の候補として素早く保存する
- 登録先プロジェクトを選択する
- 商品を候補パーツへ追加する

### 11.2 管理画面

- プロジェクトを作成・編集・削除する
- カテゴリ別の候補パーツを確認・編集・削除する
- 未分類の商品を確認し、情報とカテゴリを後から編集する
- 現在の構成に使用する商品と数量を選択する
- 互換性の判定結果を確認する
- データをバックアップ・復元する

## 12. MVPの対象外

- Webアプリ
- バックエンドサーバー
- ユーザーアカウントと認証
- 複数端末同期
- スマートフォン対応
- Chrome以外のブラウザ対応
- Chrome Web Storeでの公開
- 外部AI APIおよびAIによる抽出
- サーバー側スクレイピング
- 定期的な価格・在庫監視
- 網羅的な商品マスター
- 構成候補の自動生成
- 候補パーツ全組み合わせの総当たり互換性判定
- 複数構成案の同一プロジェクト内保存
- プロジェクト横断の共通パーツライブラリ
- プロジェクトのステータス管理
- プロジェクトの複製

## 13. 公開方針

- 汎用抽出を中心とするMVPのソースコードと文書は、公開リポジトリで管理できる
- 特定サイトへの正式対応をうたわない
- 価格.com向け専用アダプターを公開リポジトリへ含めない
- 実サイトのHTML、画像、取得した商品データをfixtureやサンプルとして含めない
- テストには架空の商品ページと架空の商品データを使用する
- リポジトリ公開とChrome Web Storeでの配布は別の判断とする
- 将来の配布版には、汎用抽出器と公開可能と判断したアダプターだけを含める

## 14. MVPの成功基準

少なくとも次を、既存のスプレッドシート運用より少ない転記作業で完了できること。

1. プロジェクトを作成する
2. Web上の商品を複数の候補として登録する
3. カテゴリ別に候補を確認する
4. 候補から現在の構成を作る
5. 基本的な互換性または情報不足を確認する
6. データをバックアップし、復元する
