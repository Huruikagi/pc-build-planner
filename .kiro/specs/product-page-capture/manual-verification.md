# product-page-capture 手動確認チェックリスト

最終更新: 2026-08-01

## このドキュメントの目的

`pnpm validate` は、production buildした未パッケージ拡張をPlaywrightから実Chromiumへ読み込み、ツールバーactionの起動、固定タブ抽出、候補管理へのhandoff、タブ失効、新しい起動世代まで自動検証する。

このチェックリストは、自動テストの代替ではなく、実サイトごとの抽出品質やブラウザ上の見た目など、人による観察が有用な範囲だけを補助確認するために使う。取り込み面は一過性であり、抽出結果の確認・補正、project解決、保存は候補管理が所有する。

## 自動テストで検証済み

| 範囲 | 検証手段 |
|---|---|
| 抽出優先順位、正規化、棄却理由、domain map | unit / contract test（架空HTML・domain） |
| 固定タブ、権限失効、制限ページ、タブ遷移、世代置換 | unit / integration / Playwright E2E |
| 抽出結果からproject未解決pre-editへのhandoff | integration / Playwright E2E |
| handoff後の元タブ失効とcandidate draftの保持・保存 | Playwright E2E |
| handoff失敗、同一世代の再試行、新世代での破棄 | unit / integration test |
| 生HTML・画像・完全URL・商品値のログ非出力 | fixture / artifact / security gate |
| unpacked MV3拡張の起動、権限、CSP、runtime error | build gate / Playwright E2E |

## 0. 事前準備

| # | 手順 | 期待結果 |
|---|---|---|
| 0-1 | `pnpm validate` を実行 | 全検証が成功する |
| 0-2 | `pnpm build` を実行 | `dist/` が生成される |
| 0-3 | `chrome://extensions` でデベロッパーモードを有効にし、`dist/` を読み込む | エラーや警告が表示されない |
| 0-4 | 拡張カードのService Workerを確認 | エラーバッジがなく、有効または非アクティブである |

## 1. 取り込みから候補編集へのhandoff

| # | 手順 | 期待結果 |
|---|---|---|
| 1-1 | PCパーツの商品ページを開き、そのタブで拡張アイコンをクリックする | サイドパネルに一過性の商品取り込み面が表示され、常設ナビに商品取り込み項目は表示されない |
| 1-2 | 「取り込みを開始」をクリックする | 処理中表示の後、一過性面が終了して候補管理のproject作成面またはcandidate editorへ移る |
| 1-3 | projectがない場合はprojectを作成する | 抽出をやり直さず、同じpre-editでcandidate editorへ進む |
| 1-4 | candidate editorの初期値を確認する | 取得できた商品名・メーカー・型番・価格・取得元が反映され、欠損値は未確認のままである |
| 1-5 | 値を補正して保存する | 候補管理の保存規則で1件だけ保存される |

_Requirements: 2.1, 2.3, 2.4, 3.5, 4.1, 4.2, 4.3, 4.6, 4.7, 5.1, 5.2, 5.3, 5.4, 5.5, 5.6_

## 2. タブ失効と世代分離

| # | 手順 | 期待結果 |
|---|---|---|
| 2-1 | アイコン起動後、抽出完了前に対象タブを更新または閉じる | 一過性面が終了し、常設面へ戻って新しい明示操作が必要であることを案内する。候補は作成されない |
| 2-2 | 再度アイコンをクリックする | 以前の失敗状態を引き継がず、新しい固定タブと起動世代でidle状態から始まる |
| 2-3 | 抽出をcandidate editorへhandoffした後に元タブを更新または閉じる | editorの入力が維持され、そのまま補正・保存できる。商品取り込み面は再表示されない |
| 2-4 | Chrome内部ページやChromeウェブストアで取り込みを試す | 対象外案内が表示され、永続状態は変化しない |

_Requirements: 1.4, 1.5, 4.3, 6.1, 6.2, 6.4_

## 3. 失敗と回復導線

| # | 手順 | 期待結果 |
|---|---|---|
| 3-1 | 商品候補を抽出できない一般ページで取り込む | 空の商品名から候補管理の手入力へ進める |
| 3-2 | handoffが失敗する条件をテスト環境で再現する | 現行世代だけに結果を保持し、同じhandoffの再試行または新しい起動を選べる |
| 3-3 | handoff失敗後に新しくアイコン起動する | 以前の保持結果と失敗状態を破棄する |

_Requirements: 4.4, 4.5, 6.3, 6.4_

## 4. 安全性とプライバシー

| # | 手順 | 期待結果 |
|---|---|---|
| 4-1 | 取り込みから保存まで実行し、サイドパネルとService WorkerのConsoleを確認する | 商品名、価格、完全URL、生HTML、例外objectが出力されない |
| 4-2 | `chrome.storage.local` の保存内容を確認する | 生HTML、画像、DOM snapshotが含まれない |
| 4-3 | markup風文字列を含む架空ページで取り込む | 文字列として扱われ、HTMLやスクリプトとして実行されない |
| 4-4 | 拡張のサイトアクセスとmanifestを確認する | 恒久的host permissionを持たず、クリック時の一時権限だけを使う |

_Requirements: 1.2, 1.3, 2.5, 3.3, 6.5, 7.4_

## 5. 抽出品質の任意サンプリング

サイト固有対応や取得率保証は対象外である。欠損は不合格ではなく、誤った値を確定値として扱わないことを重視する。

| # | 手順 | 期待結果 |
|---|---|---|
| 5-1 | 構造の異なる公開商品ページを数件試す | クラッシュ、無限待機、意図しない巡回が起きない |
| 5-2 | 抽出値とページ表示を比較する | 値と取得根拠をcandidate editorで確認・補正できる |
| 5-3 | 価格を確認する | 通貨と数値を検証できた場合だけ候補になり、不明な通貨を推測しない |
| 5-4 | メーカー公式domainでメーカー名欠損を確認する | 登録済みdomainだけが最下位候補となり、ページ由来メーカーを上書きしない |

_Requirements: 2.6, 2.7, 2.8, 2.9, 2.10, 3.2, 3.4, 3.6_

## 既知の制約

- アイコンクリックは取り込みを自動実行しない。取り込み面の明示実行が必要である。
- アイコンをクリックした固定タブだけが対象であり、別タブや後のページへ権限を拡張しない。
- 抽出結果の確認、補正、project解決、保存、保存失敗時の入力保持は候補管理が所有する。
- 取得できない項目や未分類状態は正常であり、推測で確定しない。

## 結果の記録

問題があった場合は、項目番号、Chromeバージョン、操作順、安定したエラー表示だけを記録する。商品値、完全URL、生HTML、画像、実サイト由来fixtureをリポジトリやissueへ添付しない。
