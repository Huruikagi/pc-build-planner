# product-page-capture 手動確認チェックリスト

最終更新: 2026-07-24 / 対象コミット: `tab遷移検出を本番経路で機能させfeature stylesheetを出荷bundleへ束ねる`

## このドキュメントの目的

本機能は自動テスト（unit 584件 / Playwright e2e 4件）で広く検証されているが、**Playwright/CDP には拡張機能のツールバーアイコンをクリックする手段がない**。そのため `activeTab` の実付与を前提とする `chrome.scripting.executeScript` の**取り込み成功経路だけは自動検証に到達できない**。

このチェックリストは「自動テストが原理的に到達できない範囲」に絞った手動確認項目である。自動テストで既に担保されている内容の再確認は含めない。

### 自動テストで検証済み（手動確認不要）

| 範囲 | 検証手段 |
|---|---|
| 抽出優先順位・正規化・棄却理由・ランキング | unit test（架空HTML） |
| coordinator の権限失効・制限ページ・タブ遷移・payload不正の判別 | unit test + 実port直結の統合test |
| 状態遷移・二重送信防止・保存失敗時のドラフト保持 | unit test |
| 安全描画（`dangerouslySetInnerHTML`/`innerHTML` 不使用） | DOM test |
| 診断ログへの商品値・URL非記録 | regression test（console spy） |
| MV3 unpacked extension がエラーなく読み込まれること | e2e（実Chromium） |
| `chrome.tabs.query` 実呼び出しと `permission-lost` の表示・再試行 | e2e（実Chromium） |

### 手動でしか確認できない範囲（＝以下の項目）

- `activeTab` 実付与下での `chrome.scripting.executeScript` による**実ページ抽出の成功経路**
- 実ブラウザ上での**CSS適用結果**
- 実サイトの多様なDOM構造に対する抽出品質

## 2. 【今回の修正の直接確認】

### 2-A. タブ遷移時のデータ混在防止

修正前は、`chrome.tabs.query` の解決後〜content script 注入到達までにページ遷移が確定すると、**遷移先ページの抽出値が遷移元ページのURLで保存可能状態になる**欠陥があった。

| # | 手順 | 期待結果 |
|---|---|---|
| 2-1 | リダイレクトする商品URL（短縮URL、`?utm_` 付きの正規化リダイレクト等）を開いた直後にアイコン→「取り込みを開始」 | 「取り込み中にページが移動または更新されました」または「ページの読み取りに失敗しました」が表示され、**再実行できる** |
| 2-2 | 2-1 で万一確認画面が出た場合、URL欄の値と実際に表示中のページURLを照合 | **一致していること**。不一致なら修正が効いていない |
| 2-3 | 通常の（遷移しない）商品ページで取り込み→保存し、候補管理で取得元URLを確認 | 実際に取り込んだページのURLになっている |

> 2-1 は遷移タイミングに依存するため再現しないことがある。**再現しないこと自体は失敗ではない。** 重要なのは 2-2 / 2-3 の「値とURLが食い違わない」ことの確認。

_Requirements: 6.1_

## 5. 抽出品質のサンプリング（任意）

サイト別対応は非目標のため**取得率の保証は不要**。「取れない項目があること」は仕様どおりで不合格ではない。危険なのは「誤った値が正しそうに入ること」。

| # | 手順 | 期待結果 |
|---|---|---|
| 5-1 | 構造の異なる商品ページを3〜5サイト分試す | クラッシュ・無限待機が起きない |
| 5-2 | 各サイトで取得された値と実際のページ表示を照合 | **誤った値が確認済みとして採用されていない**（取れないより誤りの方が重大） |
| 5-3 | 価格欄を確認 | 通貨と数値が分離できた場合のみ値が入る。書式不明の価格が壊れた数値として入らない |

_Requirements: 2.6, 3.2, 3.4_

## 既知の制約（不具合ではない）

- **アイコンクリックしたタブでのみ取り込める**: `activeTab` の付与範囲による Chrome の仕様。別タブへ切り替えると項目3-4の権限失効になる。
- **アイコンクリックは取り込みを開始しない**: アイコンはサイドパネルを開くのみで、取り込みはパネル内の「取り込みを開始」ボタンが担う（`chrome.action.onClicked` は `CaptureState` を共有できない service worker 上で発火するため）。
- **手入力導線のプロジェクト解決が暫定**: 項目3-3 の手入力経路は先頭プロジェクトを既定として使い、プロジェクトが0件の場合は無音で何も起きない。

## 結果の記録

不合格項目が出た場合は「項目番号 / 実際の表示 / 対象サイトのページ構造」を控えること。特に**項目1-3で「解釈できませんでした」が出た場合は今回の修正の回帰**であり、`chrome.scripting.executeScript` の `func` 戻り値と `content-script.ts` の返却形状の不整合を最初に疑う。
