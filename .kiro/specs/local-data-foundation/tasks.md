# Implementation Plan

- [ ] 1. TypeScript拡張プロジェクトと検証基盤を整える
- [ ] 1.1 厳密な型検査、ビルド、テストを実行できる開発環境を構成する
  - TypeScript、拡張バンドル、Vitestの設定とpnpmスクリプトを追加する
  - ビルド成果物を再現可能に生成し、型検査と空のテストスイートが成功する状態にする
  - `pnpm build`で未パッケージ拡張用ディレクトリが生成されることを完了条件とする
  - _Requirements: 1.1, 1.2, 7.1_
  - _Boundary: Build Infrastructure_

- [ ] 1.2 MV3 manifestとservice worker起動骨格を構成する
  - Chrome 116以降、module service worker、storage権限、最小CSPを宣言する
  - 全サイト権限、unlimitedStorage、リモートコード、インラインJavaScriptを含めない
  - Chromeが生成物をManifest V3拡張として読み込める構造になることを完了条件とする
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 5.5, 6.1_
  - _Boundary: ExtensionRuntime_

- [ ] 2. 共有ドメイン契約と入力検証を実装する
- [ ] 2.1 (P) 識別子、日時、結果型の共通規約を実装する
  - UUIDの生成・検証とUTC ISO 8601日時の生成・検証を提供する
  - 検証、移行、容量、アクセス、保存失敗を区別できる結果型を定義する
  - 有効値と無効値が型安全な結果として判別できるテストが成功することを完了条件とする
  - _Requirements: 2.5, 3.4, 3.5_
  - _Boundary: IdentifierPolicy, Result_

- [ ] 2.2 (P) プロジェクト、候補、現在構成の共有モデルを実装する
  - 全カテゴリ、欠損可能な商品情報、出典、元表記、確認値、カテゴリ別正規化属性を表現する
  - プロジェクト所属と現在構成の参照、正整数数量を表現し、業務固有の選択規則は含めない
  - 架空の全カテゴリデータが型検査を通り、生HTMLや画像を格納する専用フィールドが存在しないことを完了条件とする
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.6, 5.4_
  - _Boundary: DomainModel_

- [ ] 2.3 保存ルートと実行時スキーマ検証を実装する
  - unknown入力からフィールド、カテゴリ、UUID、UTC日時、URL、禁止データを検証する
  - プロジェクト所属と構成参照を保存ルート全体で検証し、問題pathを返す
  - 不正入力と破損ルートが正常値として返らず、架空の有効ルートだけが受理されるテストを完了条件とする
  - _Depends: 2.1, 2.2_
  - _Requirements: 2.4, 2.5, 2.6, 3.2, 3.3, 3.4, 5.4, 6.2, 7.1, 7.3_
  - _Boundary: SchemaValidator_

- [ ] 3. スキーマ移行と保存ポートを実装する
- [ ] 3.1 (P) 連続バージョン移行レジストリを実装する
  - 現行版、空ルート、入力版と出力版を明示する移行ステップを提供する
  - 各段階と最終ルートを検証し、将来版、経路欠落、検証失敗を区別する
  - 成功時のみ現行ルートを返し、失敗時に入力を変更しないテストが成功することを完了条件とする
  - _Depends: 2.3_
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5, 7.2_
  - _Boundary: MigrationRegistry_

- [ ] 3.2 (P) Chrome保存アダプターと容量状態を実装する
  - 単一保存キーの読取、書込、使用量取得、信頼済みコンテキスト制限を提供する
  - 80%警告と10MB拒否を判定し、Chrome APIのquota・権限・一般失敗を正規化する
  - 警告、拒否、アクセス制限、失敗時の既存値保持をインメモリまたはChrome APIスタブで確認できることを完了条件とする
  - _Depends: 2.1_
  - _Requirements: 3.5, 5.1, 5.2, 5.3, 5.5, 6.1, 6.3, 6.4, 7.2_
  - _Boundary: ChromeStorageAdapter_

- [ ] 4. 検証付きRepositoryを実装する
- [ ] 4.1 読取と初期化を検証・移行境界へ接続する
  - 未保存時は現行版の空ルートを返し、保存済み値は移行後に検証して返す
  - 破損、未知版、移行失敗では保存値を上書きせず識別可能なエラーを返す
  - service worker再生成を模した新Repositoryインスタンスでも同じ永続値を読めることを完了条件とする
  - _Depends: 3.1, 3.2_
  - _Requirements: 1.3, 3.3, 3.4, 4.2, 4.3, 4.4_
  - _Boundary: LocalDataRepository_

- [ ] 4.2 CRUDと参照整合性を直列更新として実装する
  - プロジェクト、候補、現在構成の作成・更新・取得・削除を最新ルートに適用する
  - 保存前に全体検証と容量確認を行い、プロジェクト削除時は所属データを同一更新で除去する
  - 有効CRUD、同内容の冪等再試行、異内容の重複競合、並行要求の直列化が統合テストで確認できることを完了条件とする
  - _Requirements: 3.1, 3.2, 3.5, 3.6, 5.1, 5.2, 5.3, 6.2_
  - _Boundary: LocalDataRepository_

- [ ] 5. ランタイム統合と公開境界を完成する
- [ ] 5.1 service worker起動時に保存アクセス制限とRepository初期化を接続する
  - 起動ごとに保存アクセスを信頼済みコンテキストへ限定する
  - 制限設定失敗時はRepositoryを利用可能として公開せず、永続状態を変更しない
  - content script向け入口やStorage APIの直接公開が生成物に存在しないことを完了条件とする
  - _Depends: 4.2_
  - _Requirements: 1.3, 6.1, 6.3, 6.4_
  - _Boundary: ExtensionRuntime, ChromeStorageAdapter_

- [ ] 5.2 下流機能向けの公開エントリポイントを整える
  - ドメイン契約、検証済みRepositoryポート、結果型だけを公開する
  - Chromeアダプターの内部詳細と未検証の保存操作を公開境界から除外する
  - 下流を模したコンシューマーが公開APIだけで型検査・CRUDできることを完了条件とする
  - _Requirements: 2.1, 3.1, 6.2, 6.3_
  - _Boundary: Public API_

- [ ] 6. 基盤全体の安全性と回帰を検証する
- [ ] 6.1 架空データによるドメイン・移行・Repository統合テストを完成する
  - 全カテゴリ、欠損値、元表記と確認値、参照整合性、禁止ペイロードを網羅する
  - CRUD、破損読取、移行成功・失敗、容量警告・拒否、アクセス拒否、再試行を検証する
  - 実サイト由来HTML、画像、商品データなしで全テストが成功することを完了条件とする
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 4.1, 4.2, 4.3, 4.4, 4.5, 5.1, 5.2, 5.3, 5.4, 6.1, 6.2, 6.3, 6.4, 7.1, 7.2, 7.3_
  - _Boundary: TestHarness_

- [ ] 6.2 manifestと生成物のMV3制約を自動検証する
  - manifest version、最低Chrome版、権限、service worker、CSPを検査する
  - リモートコード参照、eval、インラインJavaScript、host permissions、unlimitedStorageがないことを検査する
  - 型検査、テスト、ビルド、生成物検査が一つの検証コマンドで成功することを完了条件とする
  - _Requirements: 1.1, 1.2, 1.4, 5.5, 7.1, 7.3_
  - _Boundary: Build Validation_
